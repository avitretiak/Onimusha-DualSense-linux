[size=4][b]Description[/b][/size]

Onimusha-DualSense-Linux adds DualSense haptic feedback and adaptive-trigger effects to the PC version of [i]Onimusha: Way of the Sword[/i] on Linux through Proton.

The mod runs as a native Windows x64 REFramework plug-in inside the Proton game process. It provides combat, action, UI, sound-derived, and adaptive-trigger feedback.

This is an unofficial approximation. It does not reproduce the game's official PS5 implementation or effects.

[color=#ff0000][size=5][b]The Nexus submission is awaiting review. Until it is approved, the source and release downloads are available on GitHub.[/b][/size][/color]

[url=https://github.com/avitretiak/Onimusha-DualSense-linux]Onimusha-DualSense-Linux source repository[/url]

The ZIP does not contain game archives, extracted game audio, generated WAV files, or generated game-derived catalogs. Generate those files from your own game installation; do not redistribute them.

[size=4][b]Requirements[/b][/size]

[list]
[*]Linux x86_64, Steam, and Proton.
[*]A compatible REFramework installation in the game directory.
[*]A DualSense controller. USB is recommended.
[*].NET 10 runtime and Wine for local asset generation.
[*]For the optional HID relay: hidapi-hidraw, libudev, and normal user permission to access the controller. The helper does not require root.
[/list]

[size=4][b]Installation[/b][/size]

[b]1. Install REFramework.[/b]

Install a compatible REFramework release into the game directory. It should contain:

[code]
OnimushaWotS.exe
reframework/plugins/
[/code]

[b]2. Download and extract the full release ZIP.[/b]

Extract [url=https://github.com/avitretiak/Onimusha-DualSense-linux/releases/latest/download/Onimusha-DualSense-Linux-latest.zip]Onimusha-DualSense-Linux-latest.zip[/url] directly into the directory containing [font=Courier New]OnimushaWotS.exe[/font]. The archive already has the correct game-relative layout; do not put it inside another folder.

[b]3. Generate local haptic assets.[/b]

Open a terminal in the game directory and run:

[code]
cd "/path/to/game"
sh ./prepare-assets.sh .
[/code]

This is a one-time step for each release. The script extracts the required resources from the local game, generates the catalog and WAV files, and installs them under [font=Courier New]reframework/data/[/font]. It requires the .NET 10 runtime and Wine. The first run may take some time and require additional disk space.

[b]4. Set the Steam launch option.[/b]

In Steam, open the game's [font=Courier New]Properties > General > Launch Options[/font] and enter:

[code]
sh ./steam-launch.sh %command%
[/code]

Leave Steam Input enabled.

[b]5. Launch the game from Steam.[/b]

The wrapper starts the optional Linux HID relay when available and stops only the instance it started. If the relay cannot start, the game still launches; direct HID or audio output may remain available.

[size=4][b]Features[/b][/size]

[list]
[*]Haptics for combat, movement, impacts, guarding, parrying, dodging, UI actions, and other events.
[*]Sound-derived feedback generated from local game data.
[*]Bow charge resistance on R2.
[*]Rift and Soul trigger vibration on L2.
[*]Low-strength gauntlet vibration during gameplay.
[*]Native DualSense HID output and four-channel DualSense audio output.
[*]Optional Linux hidapi relay fallback.
[*]Steam Input remains available for normal game input.
[/list]

[size=4][b]Configuration[/b][/size]

Edit [font=Courier New]reframework/data/OnimushaDualSense.ini[/font]. Settings are read once at startup; restart the game after changes. Booleans accept true/false, yes/no, on/off, or 1/0. Gains range from 0.0 (off) to 1.0 (full).

[list]
[*][b]General:[/b] [font=Courier New]Enabled=false[/font] disables all mod haptic and trigger output. [font=Courier New]MasterStrength[/font] scales all output. [font=Courier New]Footsteps[/font] scales sound-derived footsteps and walk events; [font=Courier New]RunningFootsteps[/font] scales run events.
[*][b]SoundHaptics:[/b] [font=Courier New]Enabled=false[/font] disables sound-derived haptics. Set a family gain ([font=Courier New]UI[/font], [font=Courier New]Attack[/font], [font=Courier New]Cut[/font], [font=Courier New]Guard[/font], [font=Courier New]Deflect[/font], [font=Courier New]Parry[/font], or [font=Courier New]Other[/font]) to 0.0 to disable just that family.
[*][b]EventHaptics:[/b] [font=Courier New]Enabled=false[/font] disables action-event haptics; set an individual event gain to 0.0 to disable just that event. This is separate from sound-derived feedback for the same event.
[*][b]AdaptiveTriggers:[/b] [font=Courier New]Enabled=false[/font] disables all trigger effects. [font=Courier New]BowEnabled[/font] independently disables bow resistance on R2; [font=Courier New]RiftEnabled[/font], [font=Courier New]GauntletEnabled[/font], and [font=Courier New]SoulEnabled[/font] independently disable their L2 profiles. [font=Courier New]Strength[/font] scales enabled profiles; [font=Courier New]RiftStrength[/font] and [font=Courier New]SoulStrength[/font] add profile-specific gains.
[/list]

[font=Courier New]EventHaptics.BowStart[/font] controls the bow-start action haptic, not R2 resistance.

Example: disable sound-derived and action attack haptics, plus Rift and Soul L2 profiles:

[code]
[SoundHaptics]
Attack=0.0

[EventHaptics]
Attack=0.0

[AdaptiveTriggers]
RiftEnabled=false
SoulEnabled=false
[/code]

[size=4][b]Compatibility and limits[/b][/size]

The verified baseline is:

[code]
Steam game build 24769601 (AppID 2638890)
REFramework ABI 1.15.0, tested commit d1461375aee4ec3f313170f8eaad12064eb542d9
GE-Proton 11-7, Linux x86_64
USB DualSense 054c:0ce6
[/code]

Other game builds, REFramework revisions, Proton versions, architectures, and controller transports have not been verified. The optional Linux relay has been tested with the USB DualSense HID collection; Bluetooth, DualSense Edge, and other controllers are not guaranteed.

A DualSense trigger can use only one trigger mode at a time. Rift, gauntlet, and Soul are alternative L2 profiles; disabling a requested profile leaves L2 neutral rather than restoring another mode. Bow resistance on R2 remains independent. A compatible four-channel DualSense audio endpoint is needed for PCM output; HID reports remain available for action and trigger effects.

The native plug-in does not require .NET. The packaged asset generator requires the .NET 10 runtime, not the SDK.

[size=4][b]Troubleshooting[/b][/size]

[list]
[*][b]The plug-in does not load:[/b] Confirm [font=Courier New]OnimushaDualSense.dll[/font] is in [font=Courier New]reframework/plugins/[/font] and check the REFramework log.
[*][b]No haptic output:[/b] Connect one controller, try USB, close competing controller tools, and check Linux device permissions. If direct HID output is unavailable, check the optional relay's startup message.
[*][b]Asset generation fails:[/b] Run the command from the game directory and confirm [font=Courier New]OnimushaWotS.exe[/font], Wine, and the .NET 10 runtime are available.
[*][b]One trigger effect replaces another:[/b] This is expected when effects use different trigger modes; see [b]Compatibility and limits[/b].
[/list]
